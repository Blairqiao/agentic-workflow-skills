# Codex adapter

Use tools exposed in the current session and inspect their schemas. Follow [repository-local worktree placement](../workspace.md). Use a native worktree tool only if it can create checkouts inside `<main-repo>/.worktrees/`; otherwise use Git directly. Do not use Codex's managed directory as a fallback. Follow the active branch convention, normally `codex/` when no repository preference overrides it.

Use native subagents for read-only code exploration, delegated implementation, and independent review. Follow [discovery](../discovery.md#code-exploration-and-delegation) for exploration assignments and reports; documentation may be read directly by the orchestrator. Give reviewers a fresh context with [the reviewer brief](../templates/reviewer-brief.md) rather than the implementation conversation. Select available models and reasoning efforts by universal capability tier: lightweight scanning for bounded retrieval, standard coding for scoped investigations and permitted implementation, and high-reasoning for demanding investigations, architectural reasoning, independent review, and escalated fixes. Resolve exact model names and reasoning settings from the active runner rather than hardcoding them. Apply discovery's fallback when subagents or model selection are unavailable. Do not create sidebar chats as subagents.

Models may automatically invoke `orchestration-track`, `full-track`, and `fast-track` based on task scope, whereas `one-shot` keeps `agents/openai.yaml` with `allow_implicit_invocation: false`. Shared frontmatter remains portable, and the installer places `_workflow` beside the installed skills.

Use available browser inspection tools for UI verification. Existing user authorization remains subject to the session's permission controls. Report an actual permission block when it occurs rather than requesting blanket confirmation of known settings.
