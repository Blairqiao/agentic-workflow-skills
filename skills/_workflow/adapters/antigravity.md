# Antigravity adapter

Use the tools and model identifiers actually available in the active runner. When it exposes the aliases, prefer `flash` for scoped implementation, `flash_lite` for simple scanning, and `inherit` or `pro` for review or difficult fixes. Otherwise retain an available suitable model rather than assuming those aliases exist.

Give independent reviewers requirements and artifacts in a fresh context. Delegate implementation only when the selected track permits it and independent tasks justify the overhead. Follow [repository-local worktree placement](../workspace.md), using a native tool only when it accepts that path and Git directly otherwise. Harness-owned directories are not fallback locations. Use available browser tooling for UI verification.

The installer supports the configured IDE/2.0 and CLI user skill directories. Entry-skill descriptions require explicit invocation; do not infer a platform enforcement capability from that wording.
