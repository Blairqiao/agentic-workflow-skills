# Execution and delegation

Inputs: approved full or fast plan, or autonomous one-shot plan, workspace, and verification commands.

1. Maintain [the taskboard](templates/taskboard.md) at `<main-repo>/.agent-docs/taskboard/<feature>.md` for full, [the fast-track record](templates/fast-track.md) for fast, or the progress section of [the one-shot run document](templates/run.md). Update the active file in place so unfinished work is easy to find. Keep small completed items as compact checkboxes; when a taskboard grows large, move detailed completed work to `.agent-docs/archive/` and retain a short summary in the active file.
2. Implement dependency-ready tasks. Fast-track executes linearly in the current session without implementation subagents. Full-track mandates subagent delegation for task implementation, dispatching scoped subagents for each task while the orchestrator coordinates dependencies, reviews evidence, and updates the taskboard. One-shot delegates independent tasks when the benefit justifies coordination. Give simultaneous writers disjoint file scopes and isolated resources.
3. For delegated implementation, provide [a scoped implementer brief](templates/implementer-brief.md), requirements, workspace path, and relevant commands. Select subagent models by capability tier according to the active adapter. For read-only code exploration in any track, use the scoped assignment and report requirements in [discovery](discovery.md#code-exploration-and-delegation). Do not create user-visible sidebar chats as an implementation mechanism unless requested.
4. Follow [test integrity](testing.md). Inspect returned changes and recorded red and green command evidence rather than accepting unsupported claims. Reproduce relevant checks when evidence is missing, suspect, or affected by combining parallel tasks.
5. Resolve findings with concrete corrections, capping failed task implementation attempts at 3 and review-fix cycles at 3 rounds. Use [independent review](review.md) for the completed candidate and optionally earlier for high-risk tasks. Record review results before marking requirements done.

When a task fails or an approach is abandoned, update the active document in place with the current approach and a short explanation of what was tried and why it failed, moving lengthy logs or superseded plans to `.agent-docs/archive/`. If the 3-attempt or 3-round cap is reached during an in-place run, restore modified candidate files back to their pre-task state while preserving pre-existing user changes and keeping the failure record in `.agent-docs/`. Apply the track's escalation policy from [core](core.md).

Completion: required tasks are implemented and reviewed, or exhausted attempts are rolled back in place and documented with remaining blockers accurately recorded.
