# One-shot run

Request, workspace, starting state, candidate identity, and status:

## Design and acceptance criteria

Record intended behavior, non-goals, and observable requirements.

## Design decisions

For each material choice, record the options considered, chosen behavior, reasons, assumptions, and tradeoffs. Resolve product ambiguity autonomously.

## Plan and progress

Tasks, dependencies, attempt counts (capped at 3 failed attempts per task), relevant checks, outcomes, and blockers.

## Review

Method, round count (capped at 3 review-fix rounds), findings, corrections, explicit acceptance or rejection of each `test(amend)`, and whether review was independent.

## Proof

Reproducible commands, actual results, every `test(amend)` commit or in-place test revision with its reason, UI or manual evidence with embedded screenshots, candidate identity, and limitations. Follow [verification](../verification.md).

## Walkthrough

Resulting behavior, significant changes, manual steps with expected results, risks, and delivery location.

### Documentation impact

Link project guides created or updated and record unresolved documentation gaps or contradictions, or explain why no documentation changes were needed. Keep the project explanation in maintained guides and this walkthrough in the run document.

## Incomplete work

Include only when requirements remain unfulfilled. Explain the evidence and exhausted alternatives without asking for product feedback.
