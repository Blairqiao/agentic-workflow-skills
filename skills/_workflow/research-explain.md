# Explain a project

Inputs: repository, existing documentation, and user's learning goal or requested depth.

1. Locate the README, documentation index, architecture and development guides, module documentation, and `<main-repo>/.agent-docs/CONTEXT.md` when present. Follow their links to map the project's documentation structure and read the relevant documents. A list of filenames is not an explanation.
2. Check whether the existing documents provide a usable project overview and explain its major parts. A license, empty index, or unrelated boilerplate README alone does not count as usable documentation. If usable documentation is absent, disclose the need to bootstrap it and run [Audit](research-audit.md) before continuing. If explicit read-only constraints prevent writing files, provide a source-backed explanation inline and report the missing documentation instead. If documentation exists with localized gaps, explain what is available, note the gaps, and inspect the relevant source files without expanding into a full repository audit.
3. Organize the explanation around the user's goal. Start with the project's purpose and how its main parts fit together. Trace an important flow across modules, introduce canonical domain terms from `.agent-docs/CONTEXT.md`, and cover setup and verification when relevant. Link to project guides, source files, and symbols so the user can inspect them directly.
4. Use source evidence gathered under the research skill's [depth and delegation policy](../research/SKILL.md#depth-and-delegation) to support central claims and resolve ambiguous passages. Attribute unchecked statements to the document, label inferences explicitly, and separate current implementation from documented intent. Disclose contradictions with source evidence. Do not silently edit existing documentation during an explain run or imply that spot checks constitute a full audit.
5. Walk the user through focused sections and answer follow-up questions at their requested depth. For a single-summary request or one-shot run, deliver a self-contained explanation without feedback gates. Close with a recommended reading order, discovered documentation gaps, and verification limits. Apply [unslop](../unslop/SKILL.md) to all authored explanation prose.

Completion: the user has a coherent, source-linked explanation of the project at the requested depth, missing documentation has been bootstrapped through Audit when permitted, and unchecked claims, gaps, and contradictions are explicit.
